THE PROBLEM (WHY THIS MATTERS)
==============================

Aviation delay management is a $25B+ problem:

  - A 60-minute delay costs $10,000+ (fuel, crew overtime,
    passenger compensation under EU261)
  - Operations teams use Excel and react AFTER delays cascade
  - Weather disruptions at one airport propagate through the
    entire network within hours

Ireland context: Dublin Airport (DUB) handled 32M+ passengers in
2024. Ryanair (Dublin HQ), Aer Lingus, and CityJet all face these
challenges. Shannon, Cork, and Knock airports feed regional routes.
The aviation sector employs 42,000+ people in Ireland.


TECHNICAL ARCHITECTURE
======================

Layer 1: DATA INGESTION
   - BTS Transtats CSV parser with column mapping and validation
   - AWC METAR API client (Aviation Weather Center, no auth required)
   - FAA airport status API client with 15-minute cache
   - OurAirports reference data (4,553 airports with ICAO/IATA)
   - Demo data generator matching BTS schema (plug-and-play)

Layer 2: STORAGE (SQLite)
   - flights table: 37 columns, indexed on date/route/airline
   - airports table: IATA/ICAO lookup for weather API calls
   - weather_observations: METAR cache with 30-min TTL
   - airport_status_cache: FAA status with 15-min TTL
   - iata_delay_codes: 66 AHM 730 reference codes
   - predictions: ML prediction audit trail

Layer 3: ML PIPELINE
   - 18 engineered features (temporal, flight, historical, cyclical)
   - Target encoding for high-cardinality airports/airlines
   - Cyclical encoding for hour/month (sin/cos transform)
   - GradientBoostingClassifier: P(delay > 15 min)
   - GradientBoostingRegressor: estimated delay minutes
   - Temporal train/test split (prevents data leakage)
   - Performance: 77% accuracy, 0.70 AUC-ROC

Layer 4: ANALYTICS
   - OTP calculation excluding cancelled flights
   - IATA delay code mapping (BTS cause -> IATA standard)
   - Responsibility attribution (Airline/ATC/Weather/Airport)
   - Data-driven alerts (route congestion, weather spikes, cascades)

Layer 5: VISUALIZATION (Streamlit + Plotly)
   - 6 interactive tabs with 15+ chart types
   - ML prediction interface with probability gauge
   - Live weather cards with flight category color coding
   - Root cause drill-down with airport-level analysis
   - PDF export for management briefings


KEY METRICS EXPLAINED
=====================

OTP (On-Time Performance):
  (Non-delayed flights / Total non-cancelled flights) x 100
  Industry target: >80%. BTS standard: delayed = arr_delay > 15min

IATA Delay Codes (AHM 730):
  71 = Departure station weather
  81 = ATC en-route flow restriction
  93 = Late arriving aircraft (rotation)
  96 = Operations control (re-routing)
  85 = Airport security delay

BTS Delay Attribution:
  CarrierDelay    -> IATA 96 (Airline responsibility)
  WeatherDelay    -> IATA 71 (Weather)
  NASDelay        -> IATA 81 (ATC/National Airspace)
  SecurityDelay   -> IATA 85 (Airport security)
  LateAircraftDelay -> IATA 93 (Aircraft rotation cascade)
